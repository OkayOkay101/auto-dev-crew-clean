ตรวจ CI ก่อน merge

          
    
            
  • ยืดหยุ่น: repo ที่ไม่มี CI → merge ได้หลังเทสต์ในเครื่องผ่าน
    • 
            
  • บังคับ: repo ที่ไม่มี CI → ไม่ merge เลย ต้องมี CI และผ่านบน GitHub
    • 
            
  • ทั้งสองแบบ: ถ้ามี CI แล้วล้มเหลว จะไม่ merge · ตั้งรายคลังโค้ดแยกได้ที่การ์ดของแต่ละ repo
    •

โหมด merge PR

          
กำหนดว่า PR ของเอเจนต์จะให้คนรีวิวหรือ merge เองอัตโนมัติ · บันทึกเป็น merge_mode ใน config.yaml

          
          
ตั้งระดับ merge รายคลังโค้ดได้ที่แผนฟีเจอร์ใหม่ (ai-plan) · repo ที่ตั้งเองใช้ค่านั้นแทนค่ากลาง

        

      

    

    

      
📖 คำศัพท์ในหน้านี้

      

        
ช่อง (slot)
ตัวทำงาน 1 ตัว รันได้พร้อมกัน 3 ช่อง · ช่อง 1 = issue ที่คุณสั่ง · ช่อง 2–3 = หาจุดปรับปรุงเองตามบทบาท

        
judge
AI ที่ให้คะแนนโค้ดที่แก้ ต้องใช้คีย์บทบาท Judge

        
ด่านตรวจ (gate 1–4)
ด่าน 1: judge ยืนยันบั๊กก่อนแก้ · ด่าน 2: judge เห็นไฟล์เต็มหลังแก้ · ด่าน 3: รอบซ่อมต้องแตะไฟล์ที่ issue ระบุ · ด่าน 4: deep-scan ตรวจซ้ำก่อนสร้าง issue

        
key role
💻 Coder = เขียนโค้ดหลัก (ค่าเริ่มต้น) · ⚖️ Judge = ให้คะแนน · 🔍 Scan = สแกนหาปัญหา

        
F6 failover
ลำดับผู้ให้บริการที่สลับใช้เมื่อโควตาหมด ตัวบนสุดก่อน (ดูแท็บลำดับ failover)

        
ai-task
issue ที่เอเจนต์หยิบไปทำ คุณสั่งเองหรือระบบสร้างให้

        
ai-plan
issue เสนอฟีเจอร์ รออนุมัติ เมื่ออนุมัติแล้วระบบสร้าง ai-task ให้

        
deep-scan
ให้ AI อ่านโค้ดหาปัญหา ผลที่ผ่านด่าน 4 สร้างเป็น issue ai-task ได้
