การตรวจก่อน merge

      

        

          
โหมด merge PR (ค่ากลาง)

          
ตัดสินว่า PR ที่เอเจนต์เปิดจะให้คนตรวจ หรือระบบ merge เอง · บันทึกเป็น merge_mode ใน config.yaml

          
          
          
    
            
  • PR เล็ก = ไม่เกิน 50 บรรทัด (ค่า small_pr.max_lines) และไม่แตะไฟล์สำคัญ เช่น .github/, requirements
    • 
            
  • ตั้งระดับ merge รายคลังโค้ดได้ที่ แผนฟีเจอร์ใหม่ (ai-plan) ในหน้าสตูดิโอ · repo ที่ตั้งเองจะใช้ค่านั้นแทนค่ากลาง
    • 
            
  • เลือก “merge-all” ระบบจะถามยืนยันก่อน · ค่าใหม่มีผลกับการตัดสินครั้งถัดไป
    • 
          

        

        

          
ตรวจ CI ก่อน merge 

          
ดูจาก CI บน GitHub (GitHub Actions) ของ PR นั้น

          
    
            
  • ยืดหยุ่น: repo ที่ไม่มี CI → merge ได้หลังเทสต์ในเครื่องผ่าน
    • 
            
  • บังคับ: repo ที่ไม่มี CI → ไม่ merge เลย ต้องมี CI และผ่านบน GitHub
    • 
            
  • ทั้งสองแบบ: ถ้ามี CI แล้วล้มเหลว จะไม่ merge · ค่านี้เป็นค่ากลาง ตั้งรายคลังโค้ดแยกได้ในการ์ดของแต่ละ repo
    • 
          

          
        

        

          
AI ตรวจคุณภาพ (Eval / judge) 

          
judge = AI อีกตัวที่ให้คะแนนโค้ดที่แก้ก่อนเปิด PR · ไม่ผ่านเกณฑ์ระบบจะไม่เปิด PR นั้น · ต้องมีคีย์บทบาท Judge (ดูที่ คีย์ AI)

          
ปิดแล้วจะไม่มีการให้คะแนนก่อนเปิด PR

          
        

      

    

    

      
📖 คำศัพท์ในหน้านี้

      
อธิบายศัพท์ที่ใช้ทั่วทั้งหน้า ถ้าอ่านแล้วยังไม่ชัด ให้เริ่มจาก ▶ ทำ 1 งาน ในหน้าภาพรวม

      

        
ช่อง (slot)
ตัวทำงาน 1 ตัว รันได้พร้อมกัน 3 ช่อง · ช่อง 1 = issue ที่คุณสั่ง · ช่อง 2–3 = หาจุดปรับปรุงเองตามบทบาท

        
บทบาท (persona)
แนวทางของช่อง 2–3: ⚡ Bolt ความเร็ว · 🛡️ Sentinel ความปลอดภัย · 🎨 Palette หน้าตา UI · 🧪 Quality เทสต์และคุณภาพโค้ด

        
judge
AI ที่ให้คะแนนโค้ดที่แก้ ต้องใช้คีย์บทบาท Judge · เปิดหรือปิดได้ที่ ตั้งค่า › AI ตรวจคุณภาพ (Eval / judge)

        
ด่านตรวจ (gate 1–4)
ด่าน 1: judge ยืนยันว่าบั๊กใน issue มีจริงก่อนแก้ · ด่าน 2: judge เห็นไฟล์เต็มหลังแก้ ไม่ใช่แค่ diff · ด่าน 3: รอบซ่อมต้องแตะไฟล์ที่ issue ระบุ · ด่าน 4: deep-scan ตรวจซ้ำก่อนสร้าง issue

        
key role
💻 Coder = เขียนโค้ดหลัก (ค่าเริ่มต้นของทุกคีย์) · ⚖️ Judge = ให้คะแนนโค้ด · 🔍 Scan = สแกนหาปัญหาในโค้ด (ดูที่ คีย์ AI)

        
F6 failover / ลำดับสำรอง
ลำดับผู้ให้บริการ AI ที่ระบบสลับใช้เมื่อโควตาหมดหรือเรียกไม่ได้ ตัวบนสุดก่อน (ดูที่ คีย์ AI › ลำดับสำรอง)

        
ai-task
issue ที่เอเจนต์หยิบไปทำ คุณสั่งเอง หรือระบบสร้างให้จาก deep-scan, ป้าย [AI-TODO] หรือแผนฟีเจอร์ที่อนุมัติแล้ว

        
ai-plan
issue เสนอฟีเจอร์ที่รอการอนุมัติ เมื่ออนุมัติแล้วระบบจะสร้าง ai-task ให้ เอเจนต์จึงเริ่มเขียนโค้ด

        
deep-scan (สแกนลึก)
ให้ AI อ่านโค้ดทีละส่วนแล้วรายงานปัญหา ผลที่ผ่านด่าน 4 สร้างเป็น issue ai-task ได้ (กดสร้างเองหรือเปิดสร้างอัตโนมัติ)

        
merge ระดับ 1–3 (รายคลังโค้ด)
1 = คนรวมทุก PR · 2 = merge เองถ้าไม่แตะไฟล์เสี่ยง · 3 = merge เองเมื่อ CI ผ่าน
