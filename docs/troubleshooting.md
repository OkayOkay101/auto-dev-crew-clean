# การแก้ปัญหาและข้อจำกัดที่ทราบแล้ว

เอกสารนี้รวบรวมปัญหาที่พบบ่อย วิธีตรวจ และรายการข้อจำกัดที่ยังไม่ได้แก้

---

## 1. ปัญหาที่พบบ่อย

### 1.1 ไม่มีงานถูกหยิบเลย

| ตรวจ | วิธี |
|---|---|
| issue มีป้าย `ai-task` และเปิดอยู่ | ดูใน GitHub |
| ผู้เขียน issue ตรงกับ `owner` ใน `config.yaml` | ถ้าไม่ตรง ระบบจะข้าม (ไม่มีข้อความแจ้งเตือน) |
| issue ไม่มีป้าย `ai-working`, `ai-failed`, `ai-needs-human` | ถ้ามี ให้เอาออกเองถ้าต้องการให้ลองใหม่ |
| ไม่มี issue ที่เปิดอยู่ติดป้าย `ai-pause` | ถ้ามี runner จะไม่เริ่มงานใหม่ |
| repo อยู่ในรายการ `repos` และ `enabled: true` | ดูใน `config.yaml` |
| ช่องว่าง | ดูหน้า **ภาพรวม** ใน GUI |
| ช่วงเวลาตัวละคร (`personas.schedule`) | ตัวละครทำงานเฉพาะในช่วงที่ตั้งไว้ |
| โควตา engine หมด | ดูหน้า **คีย์ AI** และ log |

### 1.2 งานล้มเหลวทุกครั้ง

1. ดู log สด (หน้า **งาน**) หรือ `state/runs/` ล่าสุด
2. ถ้าเป็น `EVAL_FAILED` ให้อ่านคอมเมนต์ใน issue (มี critique จาก judge)
3. ถ้าเทสต์ล้มเหลว ให้รันเทสต์ของ repo เองในที่ทำงานเพื่อดูผลจริง
4. ถ้า engine ทำงานไม่ได้เลย ให้กด ping ที่หน้า **คีย์ AI**

### 1.3 ไม่มี engine ที่พร้อมให้ judge

ระบบจะใช้ engine ของ coder เป็น judge และบันทึกว่า `judge_same_as_coder` ถ้าต้องการให้ judge เป็นคนละตัว ให้เพิ่มคีย์บทบาท `judge` และเปิด engine นั้น

### 1.4 PR ถูกเปิดแต่ไม่ถูก merge

| สาเหตุที่เป็นไปได้ | ตรวจ |
|---|---|
| โหมดเป็น `review-all` | นี่คือพฤติกรรมที่ตั้งใจ |
| โหมด `small-only` แต่ PR เกิน `max_lines` หรือแตะ `protected_paths` | ดูจำนวนบรรทัดและไฟล์ที่เปลี่ยน |
| CI ยังไม่ผ่านหรือล้มเหลว | ดูหน้า checks ของ PR |
| repo ไม่มี CI และ `allow_no_ci: false` | เปลี่ยนค่าหรือเพิ่ม CI |
| ล็อก merge ถูกถือโดยช่องอื่นนานเกินไป | ดู log ของ `Central Merge Lock` |

### 1.5 GUI เปิดไม่ได้ หรือพอร์ตถูกใช้อยู่

- ปิดโปรเซสเก่าที่ใช้พอร์ต 8765 หรือเปิดด้วย `--port`
- ถ้า GUI ค้าง ให้รีสตาร์ท (ดู [gui.md](gui.md))

### 1.6 แก้ค่าใน `config.yaml` แล้วไม่มีผล

- รีสตาร์ทเอเจนต์ (ผลจากการแก้ค่าบางอย่างอ่านตอนเริ่มเท่านั้น)
- ถ้าแก้บทบาทคีย์ ต้องรีโหลดหน้าก่อนรีสตาร์ท
- ตรวจว่า YAML ยังถูกต้อง เช่น การเยื้องบรรทัด

### 1.7 ข้อความไทยและอังกฤษปนกัน

- หน้า UI ตามค่า `ui_language`
- log, prompt, เนื้อหา PR และข้อความ print ยังเป็นภาษาไทยทั้งหมดตามการออกแบบ (ดู `STATE.md` หัวข้อ Decisions)

### 1.8 `opencode.db` เสียหาย

```bash
python scripts/opencode_db_doctor.py          # ตรวจอย่างเดียว
python scripts/opencode_db_doctor.py --apply  # สำรองแล้วซ่อม (ปิด OpenCode ก่อน)
```

### 1.9 โฟลเดอร์ข้อมูลเปลี่ยนชื่อ

ถ้ามี `~/.ai-optimizer` เก่า ระบบจะย้ายเป็น `~/.auto-dev-crew` ครั้งเดียวตอนเริ่ม (`data_home.py`) ถ้าย้ายไม่สำเร็จ ระบบจะใช้โฟลเดอร์เก่าต่อและไม่ทำให้ข้อมูลหาย ถ้ามีโฟลเดอร์ `venvs.moved` ค้างอยู่ ลบได้ด้วยมือเมื่อไม่ต้องการแล้ว

## 3. เมื่อพบปัญหาที่ไม่อยู่ในเอกสารนี้

1. บันทึกอาการ เวลา และ log ที่เกี่ยวข้อง
2. ค้นหาข้อความ error ในโค้ด (`grep`) เพื่อหาจุดที่เกิด
3. ถ้าเป็นบั๊ก ให้เขียนเทสต์ที่ทำให้ล้มเหลวก่อน แล้วแก้ จากนั้นรันเทสต์ชุดเต็ม
4. เพิ่มรายการใหม่ในตารางข้อจำกัดหากเป็นเรื่องที่ยังแก้ไม่ได้
