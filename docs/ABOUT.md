# เกี่ยวกับ Auto Dev Crew

เอกสารนี้อธิบายว่าโปรแกรมทำงานอย่างไร ใช้ AI ตรงไหนบ้าง และตอนนี้ GUI ยังไม่สมบูรณ์ในเรื่องใด
รายละเอียดการติดตั้งและคำสั่งอยู่ใน [README.md](../README.md) ข้อกำหนดอยู่ใน [REQUIREMENTS.md](../REQUIREMENTS.md)

> สถานะ: **โครงการทดลอง / ยังไม่ production** รีโพนี้เป็น private

---

## 1. โปรแกรมนี้ทำอะไร

Auto Dev Crew เป็นเอเจนต์เขียนโค้ดที่รันบนเครื่องของผู้ใช้เอง มีเป้าหมายให้ทำงานแทนนักพัฒนาในลักษณะต่อไปนี้

- **รับงานจาก GitHub issue**: เปิด issue ใน repo เป้าหมายแล้วติดป้าย `ai-task` เอเจนต์จะหยิบไปทำ แก้โค้ด รันเทสต์ แล้วเปิด Pull Request
- **หาจุดปรับปรุงเอง**: เมื่อคิวงานว่าง ตัวละคร 4 ตัวจะสแกนโค้ดหาปัญหาตามบทบาทของตัวเอง แล้วสร้างงานให้ตัวเอง
  - `bolt` เรื่องประสิทธิภาพ
  - `sentinel` เรื่องความปลอดภัย
  - `palette` เรื่อง UX/UI
  - `quality` เรื่องเทสต์และคุณภาพโค้ด
- **ควบคุมการ merge ได้**: เลือกได้ว่าจะให้คนตรวจ merge เอง (`review-all`), merge เองเฉพาะ PR เล็กที่ไม่แตะไฟล์สำคัญ (`small-only`) หรือ merge เองทุก PR เมื่อ CI ผ่าน (`merge-all`)

ออกแบบให้ใช้งบ 0 บาท โดยหมุนเวียนผู้ให้บริการ AI หลายเจ้าเมื่อโควตาของเจ้าหนึ่งหมด

## 2. วิธีการทำงาน (ภาพรวม)

```
GitHub issue (ai-task)  หรือ  deep-scan / ตัวละคร
        │
        ▼
  runner.py: คิวงาน (มีได้ 3 ช่องพร้อมกัน)
        │  clone repo → สร้าง venv แยกต่อ repo
        ▼
  เอเจนต์ AI แก้โค้ด (ผ่าน Antigravity CLI หรือผู้ให้บริการสำรอง F6)
        │
        ▼
  เทสต์ในเครื่อง + ด่านตรวจ 1–4 (judge, ตรวจไฟล์, ตรวจซ้ำ)
        │
        ▼
  เปิด Pull Request → ตรวจ CI บน GitHub → merge ตามโหมดที่ตั้งไว้
```

### องค์ประกอบหลัก

| ส่วน | หน้าที่ |
|---|---|
| `auto_dev_crew/runner.py` | คิวงาน, clone, เรียกเอเจนต์, เทสต์, เปิด PR, merge, รายงาน |
| `auto_dev_crew/gui.py` | เว็บ GUI ในเครื่อง (`127.0.0.1:8765`) สั่งงาน ดูบันทึก ตั้งค่า |
| `auto_dev_crew/providers.py`, `keys.py` | รายชื่อผู้ให้บริการ AI และการจัดการคีย์ |
| `auto_dev_crew/routing.py` | จัดลำดับผู้ให้บริการตามผล merge ย้อนหลัง (ดู `state/history.json`) |
| `auto_dev_crew/redact.py` | ซ่อน token/คีย์ก่อนแสดงหรือบันทึก log |
| `auto_dev_crew/static_gate.py`, `quality_gates.py` | ด่านตรวจความปลอดภัยและคุณภาพก่อนเปิด PR |
| `prompts/` | prompt ของงาน issue, การซ่อมเทสต์, และตัวละครทั้ง 4 (`_rules.md` คือกฎร่วม) |

### แนวคิดที่ควรรู้

- **ช่อง (slot)**: รันได้พร้อมกันสูงสุด 3 งาน ช่อง 1 ทำ issue ที่ผู้ใช้สั่ง ช่อง 2–3 หาจุดปรับปรุงเอง
- **F6 failover**: เมื่อโควตาของผู้ให้บริการตัวหนึ่งหมด ระบบสลับไปตัวถัดไปตามลำดับใน `config.yaml`
- **ด่านตรวจ 1–4**: ด่าน 1 judge ยืนยันว่าบั๊กมีจริงก่อนแก้ ด่าน 2 judge ดูไฟล์เต็มหลังแก้ ด่าน 3 ตรวจว่ารอบซ่อมแตะไฟล์ที่ issue ระบุ ด่าน 4 deep-scan ตรวจซ้ำก่อนสร้าง issue
- **ai-plan**: ข้อเสนอฟีเจอร์ที่รอการอนุมัติ เมื่ออนุมัติแล้วระบบสร้าง `ai-task` ให้
- **ai-pause**: ติดป้ายนี้บน issue ใดก็ได้เพื่อหยุดเอเจนต์ฉุกเฉิน
- **ความจำ**: `state/history.json` เก็บว่าเคยเสนออะไรไปแล้วและผล merge ไม่ถูก commit

### ขอบเขตการรันและความปลอดภัย

- GUI เปิดให้เฉพาะเครื่องนี้ (`127.0.0.1`) คำสั่งที่เปลี่ยนแปลงข้อมูล (POST) ต้องมี token ที่ฝังในหน้าเว็บ และ endpoint ที่อ่านข้อมูล repo บางตัวก็ต้องมี token ด้วย
- คีย์ API อยู่ในไฟล์ `.env` ซึ่งอยู่ใน `.gitignore` และไม่ถูกส่งขึ้น GitHub
- ข้อห้าม force-push และ push เข้า `main` ตรง ๆ เป็นกฎที่เขียนไว้ในเอกสาร ส่วนสคริปต์ guard ของโหมดอัตโนมัติ (`scripts/autonomous_guard_hook.py`) บล็อก `git push`, `git reset --hard`, `git clean -f` และ `rm -rf` แบบต่าง ๆ โดย**ไม่ได้บล็อก force-push โดยเฉพาะ**
- โค้ดที่เอเจนต์เขียนต้องผ่านเทสต์ ด่านตรวจ และ CI ก่อน merge แต่ **ไม่ได้ผ่านการตรวจความปลอดภัยโดยผู้เชี่ยวชาญ**

## 3. การใช้ AI ในการสร้างโปรแกรมนี้

**โปรแกรมนี้ถูกสร้างด้วยความช่วยเหลือของ AI** โดยผู้พัฒนาใช้ Claude Code (โมเดล Claude) เป็นผู้ช่วยเขียนและแก้โค้ดภายใต้การกำกับของผู้พัฒนา

- งานหลายชิ้นในโปรเจกต์ทำร่วมกับ AI เช่น การแปลข้อความ GUI, การลบระบบล็อกอิน และการแก้เทสต์ที่ flaky บันทึกความคืบหน้าอยู่ใน `STATE.md` และ `docs/superpowers/`
- ผู้พัฒนาเป็นผู้กำหนดเป้าหมาย ตัดสินใจเรื่องสถาปัตยกรรม และยืนยันผลการทำงาน
- ผลทดสอบที่บันทึกไว้ใน `STATE.md` คือ `pytest` ผ่าน 1442 รายการ ข้าม 6 รายการ ณ วันที่ 2026-11-18
- **โค้ดที่ AI เขียนอาจมีบั๊กหรือช่องโหว่ที่ยังไม่ถูกพบ** จึงควรอ่านและทดสอบก่อนนำไปใช้จริง

นอกจากการพัฒนาแล้ว ตัวโปรแกรมเองก็ **ใช้ AI ขณะรันงาน** ด้วย โดยส่งโค้ดของ repo เป้าหมายไปให้ผู้ให้บริการ AI ที่ตั้งไว้ (Antigravity, OpenCode, NVIDIA Build, Pollinations.ai, Mistral) ดังนั้นโค้ดของ repo นั้นจะถูกส่งออกไปยังผู้ให้บริการเหล่านั้นตามการตั้งค่า

## 4. สถานะ GUI: ยังไม่สมบูรณ์

GUI ใช้งานได้ในภาพรวม แต่**ยังไม่สมบูรณ์** รายการที่ทราบแล้วมีดังนี้

| เรื่อง | สถานะ |
|---|---|
| การแปลภาษา (ไทย/อังกฤษ) | แปลข้อความหลักใน `gui.py` และข้อความ error ฝั่ง backend แล้ว แต่ **log, เนื้อหา PR body และ print** ยังคงเป็นภาษาเดิม |
| ระบบล็อกอิน | ถูกลบออกทั้งหมดแล้ว (GUI พึ่งการผูกกับ `127.0.0.1` แทน) |
| หน้า `/classic` (แท็บบนสุด) | ลบแล้ว (2026-11-18) |
| endpoint `/api/github/*` และ `github_login.py` | ลบแล้ว (2026-11-18) เพราะ UI ไม่ได้ใช้ |
| การหยุดเมื่อคะแนนค้าง (`check_convergence`, `evaluator.py`) | ทำงานในลูปซ่อมหลังประเมิน (`runner.py`) เมื่อ `evaluation.plateau_stop` เป็น true (ค่าเริ่มต้น) ถ้าคะแนนไม่ดีขึ้นจะหยุดรอบซ่อม |
| โหมดง่าย (Simple mode) | ถูกลบออกแล้วตามการตัดสินใจ |
| การทดสอบบนอุปกรณ์จริง | ทดสอบบนเบราว์เซอร์ในเครื่องแล้ว **ยังไม่ได้ทดสอบครบทุกเบราว์เซอร์และทุกขนาดหน้าจอ** |

หากพบปัญหาใน GUI ที่ไม่อยู่ในตารางนี้ ให้ถือว่ายังไม่ได้ตรวจและรายงานมาได้

## 5. ข้อควรระวังก่อนใช้งาน

- **ห้าม commit หรือแชร์ไฟล์ `.env`** และห้ามพิมพ์ค่าคีย์ลงใน log หรือแชต
- `config.yaml` เป็นค่าเฉพาะของเจ้าของ README ระบุว่าไม่ควร commit ไฟล์นี้ ปัจจุบันไฟล์นี้ยังถูก track อยู่ในรีโป
- การ merge อัตโนมัติ (`merge-all`) เสี่ยงที่โค้ดที่ยังไม่ได้ตรวจโดยคนจะเข้าสู่ branch หลัก ควรเริ่มด้วย `review-all`
- ใช้ `--dry-run` ทดลองก่อนเสมอเมื่อเปลี่ยนค่าตั้งค่าหรือ repo ใหม่
