## 1. เจตนาและเหตุผล

ผู้ใช้ต้องการให้โปรแกรม Auto Dev Crew ทำงานได้เต็มรูปแบบทั้งภาษาไทยและอังกฤษ
ทั้งหน้าเว็บ (`auto_dev_crew/static/*`) และข้อความที่ Backend (`auto_dev_crew/*.py`) ส่งให้ผู้ใช้เห็น
ค่าเริ่มต้นยังเป็นไทย และผู้ใช้สลับภาษาได้จาก UI

สถานะปัจจุบันจากการตรวจโค้ด (2026-11-18):

- ข้อความไทยเป็นต้นฉบับ (source text) ฝังอยู่ในโค้ดโดยตรง
- **มีกลไกแปลสองแบบซ้อนกันอยู่:**
  1. `static/index_sidebar.html` มีตาราง `const EN_TEXT` (บรรทัด ~1598) และ `data-i18n` กับฟังก์ชัน `applyLang`
  2. `static/i18n.js` + `static/i18n_en.js` (1,344 รายการ) แทนข้อความด้วยการค้นหาข้อความย่อย (substring) ตอนรันในเบราว์เซอร์
- `i18n.js` มีโค้ดพิเศษ เช่น การเว้นวรรคระหว่างคำอังกฤษกับตัวอักษรไทย (บรรทัด 52) ซึ่งบอกว่ากลไกนี้เปราะบาง
- ปุ่มสลับภาษาเก็บค่าใน `localStorage` และต้องโหลดหน้าใหม่ ข้อความที่แปลแล้วกลับเป็นไทยโดยไม่โหลดใหม่ไม่ได้
- Backend ไม่มีการตั้งค่าภาษาเลย ข้อความที่เป็นไทยมีประมาณ 1,000 บรรทัดในไฟล์ `.py`
  (มากที่สุด: `runner.py` ~244, `gui.py` ~173, `keys.py` ~74, `quality_gates.py` ~42)
- ไฟล์ HTML/JS ที่ผู้ใช้เห็นมีประมาณ 1,550 บรรทัดที่มีไทย (`index_sidebar.html` 926, `index.html` 587, `mission_control.js` 30, `login.html` 5)
- มีการทดสอบอยู่แล้วใน `tests/test_i18n_english_coverage.py` (7 เคส) ซึ่งตรวจว่าข้อความมีคำแปลในพจนานุกรม

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ห้ามเกิด

**เป้าหมาย**

- ทุกข้อความที่ UI แสดง (หน้าหลัก, `/classic`, หน้า login, toast, confirm/alert, สถานะงาน) มีทั้งไทยและอังกฤษ
- ข้อความที่ Backend ส่งให้ UI (error, status, label, ข้อความใน CLI ที่ผู้ใช้เห็น) ตามภาษาที่ตั้งไว้
- ค่าเริ่มต้นเป็นไทย ผู้ใช้สลับได้โดยไม่ต้องแก้โค้ด
- มีการทดสอบอัตโนมัติที่ล้มเหลวทันทีถ้าคีย์ขาดในภาษาใดภาษาหนึ่ง

**ไม่ใช่เป้าหมาย (ค่าเริ่มต้นของการออกแบบ ผู้ใช้ยืนยันได้)**

- ไม่แปล **ข้อมูลจริงของผู้ใช้**: ชื่อ issue, ชื่อ repo, โค้ด, diff, log ดิบจากเอเจนต์/เอนจิน
- ไม่แปลไฟล์เอกสาร (README, docs) ในรอบนี้

**สิ่งที่ห้ามเกิด (anti-goals)**

- ห้ามใช้การค้นหาข้อความย่อยแบบเดิมต่อไป (เปราะบาง ทับข้อมูลจริงได้)
- ห้ามมีแหล่งความจริงสองแห่งสำหรับข้อความเดียวกัน
- ห้ามให้ภาษาอังกฤษหล่นกลับเป็นไทยเงียบ ๆ โดยไม่มีการทดสอบจับได้

## 5. รายละเอียดของแนวทาง B (ตามที่เสนอ)

### 5.1 การเลือกภาษา
- เก็บใน `config.yaml` เป็นคีย์ `ui_language: th` (ค่าที่รับได้: `th`, `en`; ค่าเริ่มต้น `th`)
- เหตุผล: Backend (รันเบื้องหลัง, CLI, การแจ้งเตือน, ไฟล์สถานะ) ต้องรู้ภาษาเดียวกับหน้าเว็บ ถ้าเก็บใน `localStorage` อย่างเดียว Backend จะไม่รู้
- ปุ่มสลับใน UI เรียก API ที่ต้องมี token (ตามระบบที่มีอยู่) เขียน `config.yaml` แล้วโหลดหน้าใหม่
- ค่าที่ผู้ใช้เคยเก็บใน `localStorage` ("adc_lang") ไม่ใช้แล้ว (ลบโค้ดเดิมที่บังคับเป็นไทยครั้งเดียว)
- **เรื่องที่ผู้ใช้ต้องตัดสิน:** ยอมรับ config.yaml หรือต้องการ localStorage อย่างเดียว (ดูข้อ 9)

### 5.2 โครงสร้างไฟล์
```
auto_dev_crew/
  i18n.py                # t(key, lang=None, **params), load_locale(), get_language()
  locales/
    th.json              # แหล่งความจริงภาษาไทย
    en.json              # แหล่งความจริงภาษาอังกฤษ
  static/
    i18n.js              # ใหม่: โหลดพจนานุกรม, t(), applyI18n(), setLanguage()
    (ลบ) i18n_en.js       # เมื่อย้ายครบ
```
- JSON แบบ flat keys เพื่อตรวจง่าย ค่าเป็นข้อความ (ไม่มี HTML; ถ้าจำเป็นใช้ `data-i18n-html` แยก)

### 5.3 ขอบเขตฝั่ง Backend ที่ต้องแปล
| ประเภท | ตัวอย่าง | แปลหรือไม่ |
|---|---|---|
| ข้อความ error ที่ API ส่งให้ UI | `{"error": "..."}` | แปล |
| ป้ายสถานะ (label) ของงาน, slot, issue | เดิมเป็นข้อความไทยในโค้ด | แปล (เปลี่ยนเป็น enum + คีย์) |
| ข้อความที่ CLI/doctor/key_ping แสดง | ผลตรวจสุขภาพ | แปล |
| ข้อความใน log ไฟล์ของ slot | บรรทัดที่เขียนลง `slot_N.log` | **ผู้ใช้ตัดสิน** (ข้อ 9) |
| prompt ที่ส่งให้เอนจิน AI (`quality_gates.py`, palette ใน `runner.py`) | เทมเพลตไทย | **ไม่แปลในรอบนี้** (AI อ่าน ไม่ใช่ผู้ใช้; เปลี่ยนภาษาจะเปลี่ยนพฤติกรรม AI) ผู้ใช้ตัดสิน (ข้อ 9) |
| เนื้อหา PR body / commit message ที่ส่งไป GitHub | `pr_body.py` | **ผู้ใช้ตัดสิน** (ข้อ 9) |
| ข้อมูลจริง (ชื่อ issue, log ดิบจากเอเจนต์) | ข้อความที่ผู้ใช้/เอนจินเขียน | ไม่แปล |

### 5.4 ลำดับการย้าย (migration) เป็นขั้น
1. สร้าง `i18n.py`, `locales/th.json`, `locales/en.json` (ดึงข้อความไทยจาก EN_TEXT, i18n_en.js ตามคู่ที่มี) และเทสตรวจคีย์
2. ย้ายหน้า `index_sidebar.html` ก่อน (หน้าหลัก) แล้วลบ `EN_TEXT` และ `applyLang` เดิม
3. ย้าย `index.html` (classic), `login.html`, `mission_control.js`
4. ย้ายข้อความ Backend ทีละโมดูล (`gui.py` ที่สุดก่อน, แต่ดูข้อ 8)
5. ลบ `i18n_en.js`, `i18n.js` เดิม และการทดสอบเก่าที่ตรวจด้วยพจนานุกรมเดิม
6. รัน pytest เต็ม และทดสอบ GUI ด้วย browser ทั้งสองภาษา

## 6. เทสที่จะเพิ่ม (ระดับแผน ยังไม่เขียน)

- **ความครบถ้วนของคีย์:** `th.json` และ `en.json` มีคีย์ชุดเดียวกัน ไม่มีค่าว่าง
- **ไม่มีคีย์ที่ไม่ได้ใช้** และ **ไม่มีคีย์ที่ใช้แล้วแต่ไม่มีในพจนานุกรม** (สแกน `data-i18n`, `t("...")`, `t(...)` ในโค้ด Python)
- **ไม่มีข้อความไทยหลุดในไฟล์ UI** ของ `en` (ตรวจ `en.json` และ HTML/JS ที่ผู้ใช้เห็น เฉพาะที่ไม่อยู่ใน allowlist)
- **Backend:** `t()` คืนค่าตามภาษาที่ตั้ง, ตัวแปรถูกแทน, ภาษาที่ไม่รู้จักตกกลับเป็นไทย
- **Frontend:** สลับภาษาแล้วหน้าทั้งหน้าเป็นภาษาอังกฤษ (ทดสอบด้วย browser จริง)
- เทสเดิมที่มีคำไทยใน assert จะถูกปรับให้ตรวจผ่านคีย์ ไม่ใช่ข้อความดิบ

## 9. เรื่องที่ต้องให้ผู้ใช้ตัดสิน (ก่อนเขียนแผน)

1. **อนุมัติแนวทาง B** หรือจะเลือก A/C/D
2. **เก็บภาษาใน `config.yaml` (แนะนำ)** หรือเก็บใน `localStorage` อย่างเดียว

ผู้ใช้อนุมัติแนวทาง B แล้ว ระหว่างทำพบและปรับดังนี้ (ทำให้ตรงกับโค้ดจริง):

- **คีย์ = ข้อความไทยต้นฉบับ** (ไม่ใช่ `ส่วน.ชื่อ`) เหตุผล: พจนานุกรมเดิมใช้ไทยเป็นคีย์อยู่แล้ว และค่าเริ่มต้นไทยจึงไม่เปลี่ยนเลยทุกตัวอักษร
- **มี `auto_dev_crew/locales/en.json` เพียงไฟล์เดียว** ไม่มี `th.json` (ไม่มีไฟล์ = ใช้ข้อความไทยที่เป็นคีย์เอง) ตารางแปลเดิม (`i18n_en.js` 1,338 รายการ + `EN_TEXT` 93 รายการ) รวมเป็น `en.json` แล้วลบ `i18n_en.js` และ `EN_TEXT`
- **ฝั่งเว็บ:** `static/i18n.js` ให้ `window.i18n(key, params)`, `window.applyI18n()`, `window.setLanguage(lang, token)` และ `window.adcLang` ชื่อ `t` ไม่ใช้ เพราะชนกับตัวแปร `t` ในโค้ดเดิม
- **แทนข้อความ:** ข้อความใน HTML ใช้ `data-i18n` (ข้อความล้วน) หรือ `<span data-i18n>` (ข้อความปนกับแท็กลูก) และ `data-i18n-attr` สำหรับ attribute. ใน JS ใช้ `i18n("...")` และ template literal แยกเฉพาะช่วงข้อความไทยเป็น `${i18n("...")}`
- **ฝั่ง Backend:** `auto_dev_crew/i18n.py` มี `t(key, lang=None, **params)` (ใช้ `_i18n.t(...)` ในโมดูล) ข้อความที่ผู้ใช้เห็นที่ถูกแปลแล้ว: error ที่โยนหรือคืนค่า, ผลลัพธ์ CI step, ผลประเมิน, ข้อความ provider/key/engine. ยังเป็นไทยตามค่าเริ่มต้น: log/say/print, prompt ของ AI, PR body/issue body, และ `gui.py`, `auth.py`, `github_login.py`, `quality_gates.py`, `pr_body.py` (ยังไม่ได้ทำ ดูข้อ 14)

## 14. สิ่งที่ยังไม่เสร็จ (ต้องรอ)
