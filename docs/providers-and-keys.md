# ผู้ให้บริการ AI และการจัดการคีย์

เอกสารนี้อธิบายว่าระบบเชื่อมกับผู้ให้บริการ AI อย่างไร เพิ่มผู้ให้บริการใหม่ได้อย่างไร และกำหนดบทบาทของคีย์อย่างไร

---

## 1. แนวคิด

| คำ | ความหมาย |
|---|---|
| ผู้ให้บริการ (provider) | บริการ AI เช่น Pollinations.ai, NVIDIA Build, Google AI Pro |
| engine | ตัวรันหนึ่งตัวที่ระบบเรียก ประกอบด้วยโปรแกรม (`agy` หรือ `opencode`) + โมเดล + คีย์ |
| คีย์ (key) | ค่า API ที่เก็บใน `.env` มีบทบาท (role) กำกับ |
| บทบาท (role) | `coder` เขียนโค้ดหลัก, `judge` ให้คะแนน, `scan` สแกนหาปัญหา |
| F6 failover | สลับไป engine ตัวถัดไปเมื่อตัวปัจจุบันโควตาหมดหรือ timeout |

ความสัมพันธ์: หนึ่งผู้ให้บริการมีได้หลายคีย์ และหนึ่ง engine ใช้คีย์หนึ่งชุด (รายการ `api_keys`) บทบาทของ engine มาจาก `roles` ใน config หรือจากการจับคู่บทบาทของคีย์ใน `state/key_roles.json`

---

## 2. ทะเบียนผู้ให้บริการ

ทะเบียนอยู่ที่ `state/providers.json` (สร้างจาก `opencode.json` ตอนเริ่มครั้งแรก) โครงสร้าง:

```json
{
  "pollinations": {
    "display_name": "Pollinations.ai",
    "base_url": "https://...",
    "key_var": "POLLINATIONS_API_KEY_1"
  }
}
```

กฎการตั้งชื่อใน `auto_dev_crew/providers.py`:
- รหัสผู้ให้บริการ (id) ต้องเป็นอักษรอังกฤษพิมพ์เล็ก ตัวเลข หรือขีดกลาง ยาว 2–31 ตัว เช่น `deepseek`
- URL ต้องขึ้นต้นด้วย `https://` และห้ามมีช่องว่าง
- ชื่อตัวแปรคีย์มาตรฐานคือ `<ID พิมพ์ใหญ่และขีดกลางเป็นขีดล่าง>_API_KEY_1` เช่น `deepseek` → `DEEPSEEK_API_KEY_1`

ทุกครั้งที่เพิ่มผู้ให้บริการ ระบบจะ sync ค่า `baseURL` และ `apiKey` ไปยัง `opencode.json` โดยไม่ลบรายการโมเดลที่มีอยู่ ถ้าขั้นหลังล้มเหลว engine ที่เพิ่มไปแล้วจะถูก rollback

---

## 3. เพิ่มผู้ให้บริการใหม่

### วิธีที่ 1: ผ่าน GUI (แนะนำ)
1. เปิดหน้า **คีย์ AI**
2. เลือกเพิ่มผู้ให้บริการ (`POST /api/provider/add`)
3. กรอกรหัส, URL (https), ชื่อที่แสดง และคีย์
4. ระบบเขียนคีย์ลง `.env`, เพิ่มทะเบียน, sync `opencode.json` และเพิ่ม engine ให้ในครั้งเดียว

### วิธีที่ 2: แก้ด้วยมือ
1. ใส่คีย์ใน `.env` ด้วยชื่อที่ตรงกับ `key_var`
2. เพิ่ม engine ใน `config.yaml` ใต้ `engines`
3. รีสตาร์ทเอเจนต์

หลังเพิ่มแล้วควรกด **ping** คีย์ (`POST /api/keys/ping`) เพื่อตรวจว่าเรียกได้จริง

---

## 4. คีย์ใน `.env`

- ชื่อตัวแปรรูปแบบ `<PROVIDER>_API_KEY_<n>` โดย `<n>` เริ่มที่ 1 ใส่ได้หลายชุดเพื่อให้สลับคีย์เมื่อโควตาชุดหนึ่งหมด
- ตัวท้าย `_JUDGE`, `_SCAN`, `_CODER` ทำให้คีย์นั้นได้บทบาทนั้นโดยอัตโนมัติ ถ้าไม่ได้ตั้งเองในหน้าคีย์ (`keys.py`, `_DOTENV_ROLE_SUFFIX_RE`)
- ค่าคีย์ไม่ควรถูกคัดลอกลง log, issue, แชต หรือ commit ระบบซ่อนค่าที่รู้จักใน log แต่ไม่ควรพึ่งพาเป็นหลัก
- ตรวจได้เฉพาะชื่อตัวแปรและความยาวค่า ไม่ใช่ตัวค่า

---

## 5. บทบาท (role)

| บทบาท | ทำอะไร | หมายเหตุ |
|---|---|---|
| `coder` | เขียนโค้ดหลังรับโจทย์ | ค่าเริ่มต้นของคีย์ทุกตัว |
| `judge` | ให้คะแนนตาม rubric | ควรเป็นคนละ engine กับ coder (ถ้าเป็นตัวเดียวกันระบบจะบันทึกไว้) |
| `scan` | สแกนหาปัญหา (deep-scan และตัวละคร) | |

- การกำหนดบทบาทต่อคีย์ทำได้ที่ **คีย์ AI** (`POST /api/key/roles`) บันทึกใน `state/key_roles.json` (จำกัดให้เป็น `coder`, `judge`, `scan` เท่านั้น)
- การกำหนดบทบาทต่อ engine ใน `config.yaml` ที่ฟิลด์ `roles`
- หลังเปลี่ยนบทบาท **ต้องรีโหลดหน้า แล้วรีสตาร์ท** เอเจนต์

---

## 6. ลำดับสำรอง (failover)

- ลำดับที่ใช้จริงคือลำดับใน `engines` ของ config หรือลำดับที่ `routing` จัดใหม่ตามผลประวัติ (ถ้า `routing.enabled` เป็น true)
- ปรับลำดับใน GUI ได้ที่ `POST /api/engine/reorder`
- engine ที่ timeout จะถูกพัก `engine_timeout_cooldown_minutes` นาที
- engine ที่โควตาหมดจะถูกข้ามและสลับไปตัวถัดไป

---

## 7. การนับโควตาและการใช้งาน

- ทุกคำขอบันทึกลง `state/usage.jsonl` (จำนวนคำขอและ token)
- หน้า **คีย์ AI** แสดงการใช้งานวันนี้ต่อ engine
- ค่าโควตาที่ระบบรู้จักมาจากการนับเอง ไม่ใช่จากผู้ให้บริการโดยตรง ดังนั้นอาจไม่ตรงกับยอดจริงของบัญชี

---

## 8. ข้อควรระวังด้านความเป็นส่วนตัว

- `trains_on_data` ใน engine เป็นค่าประกอบการตัดสินใจ ระบบไม่ได้บังคับให้ผู้ให้บริการไม่เทรนข้อมูล ให้ตรวจนโยบายของผู้ให้บริการเอง
- โค้ดของ repo เป้าหมายถูกส่งไปยัง engine ที่ทำงานภายนอกเครื่อง ไม่ควรใช้กับ repo ที่มีข้อมูลลับที่ไม่อยากให้ผู้ให้บริการเห็น
- engine ที่ `enabled: false` จะไม่ถูกเรียก

---

## 9. เมื่อคีย์ใช้ไม่ได้

| อาการ | ตรวจอะไร |
|---|---|
| ping ไม่ผ่าน | ชื่อตัวแปรใน `.env` ตรงกับ `key_var` หรือไม่ และค่ายังไม่หมดอายุ |
| engine ไม่ทำงานแต่คีย์ปกติ | `command` และ `path` ชี้ไปยังโปรแกรมที่มีอยู่จริงหรือไม่ |
| judge ใช้ engine เดียวกับ coder | ไม่มี engine ที่มีบทบาท judge เปิดอยู่ ให้เพิ่มคีย์ judge |
| ได้คะแนนต่ำตลอด | ดู critique ใน PR หรือ log และพิจารณาเปลี่ยน judge |
