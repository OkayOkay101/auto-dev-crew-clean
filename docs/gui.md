# คู่มือหน้าควบคุม (GUI)

GUI เป็นเว็บเซิร์ฟเวอร์ในเครื่องที่สร้างด้วย `http.server` ของ Python โดยไม่มี framework ภายนอก

- ที่อยู่: `http://127.0.0.1:8765/` (เปลี่ยนพอร์ตได้ด้วย `--port`)
- ผูกกับ `127.0.0.1` เท่านั้น จึงเข้าจากเครื่องอื่นในเครือข่ายไม่ได้โดยตรง
- หน้า `/classic` คือหน้าเดิมแบบแท็บบนสุด ยังคงอยู่ระหว่างรอการตัดสินใจว่าจะเก็บหรือลบ

## 1. ความปลอดภัยของ GUI

- **Token:** ทุกครั้งที่เซิร์ฟเวอร์เริ่ม จะสร้าง token แบบสุ่ม (`secrets.token_urlsafe`) ฝังในหน้าเว็บ คำสั่งที่เปลี่ยนแปลงข้อมูล (POST) ต้องส่ง token นี้ในหัวข้อ `X-Token` เพื่อกันเว็บไซต์อื่นที่เปิดในเบราว์เซอร์เดียวกันส่งคำสั่งมาได้
- **Endpoint ที่อ่านข้อมูล repo บางตัว** ก็ต้องมี token ด้วย ได้แก่ `/api/repo/file-content`, `/api/byop/status`, `/api/byop/pool`
- **ขนาด body:** สูงสุด 1 MB ต่อคำขอ เกินนั้นได้รับ `413`
- **การยืนยันก่อนทำงานจริง:** ปุ่มที่สแกนหรือสร้าง issue ถามยืนยันก่อน (`confirm()`) ไม่ควรข้ามด้วย JavaScript
- **ข้อจำกัด:** ไม่มีการล็อกอินรหัสผ่านใน GUI (ระบบล็อกอินถูกลบไปแล้ว) การเข้าจากนอกเครื่องต้องใช้ SSH tunnel หรือวิธีอื่นที่ผู้ดูแลตั้งเอง

## 2. เมนูซ้าย 5 หน้า

### 2.1 ภาพรวม (Overview)
- **▶ ทำ 1 งาน:** ทำหนึ่งชิ้นแล้วหยุดเอง
- **⟳ ทำต่อเนื่อง:** เริ่มโหมด `--loop` ทำไปเรื่อย ๆ จนกดหยุดหรือหมดงาน
- **■ หยุด:** ยกเลิกงานที่กำลังทำ มีการถามยืนยันก่อน
- **🔄 รีสตาร์ท:** อยู่ในหัวข้อ "เพิ่มเติม" ผลคือยกเลิกงานที่กำลังทำแล้วเริ่มรอบใหม่ด้วยค่าเดิม PR ที่เปิดแล้วไม่ถูกปิด
- **ช่องทำงาน 3 ช่อง:** แสดงสถานะของช่อง 1–3 และสามารถกำหนด persona หรือ repo ให้ช่องได้
- **การ์ดคลังโค้ด:** แสดง repo แต่ละตัวพร้อมสถานะ เปิด/ปิด และระดับ merge
- **ป้าย `merge:`** มุมขวาบนแสดงค่า `merge_mode` ปัจจุบัน

**ก่อนรีสตาร์ทหรือหยุด:** ดูว่าช่องว่างหรือไม่ ถ้ามีงานกำลังทำ งานนั้นจะถูกยกเลิก

### 2.2 งาน (Jobs)
- **บันทึกสด (live log):** log ของ runner แสดงแบบเรียลไทม์
- **ประวัติงาน:** รายการงานที่ผ่านมา กดดู diff ได้

### 2.3 สตูดิโอ (Studio)
- สั่ง AI แก้โค้ดใน repo ที่เลือก
- ดู diff ที่ได้
- หา `[AI-TODO]` และสร้าง issue จากผล
- สแกนลึก (deep-scan) ดู [architecture.md](architecture.md#10-deep-scan)
- แผนฟีเจอร์ (`ai-plan`) ดู [github-workflow.md](github-workflow.md#4-แผนฟีเจอร์-ai-plan)

### 2.4 คีย์ AI (Keys)
- ดูและเพิ่มคีย์ของผู้ให้บริการ
- กำหนดบทบาท coder, judge, scan
- ลำดับสำรอง (failover) ของ engine
- ประวัติการใช้งานล่าสุดต่อวัน (จาก `state/usage.jsonl`)

รายละเอียดที่ [providers-and-keys.md](providers-and-keys.md)

### 2.5 ตั้งค่า (Settings)
- โหมด merge (`review-all`, `small-only`, `merge-all`)
- การตรวจ CI (`allow_no_ci`)
- การตรวจคุณภาพ (judge) เปิด/ปิด
- ภาษาของ UI (`th` / `en`)
- **คำศัพท์:** อธิบายคำศัพท์ทั้งหมดของระบบ
- **ปิดเซิร์ฟเวอร์**

## 3. คำศัพท์ที่เห็นในหน้า

| คำ | ความหมาย |
|---|---|
| ช่อง (slot) | ตัวทำงานหนึ่งตัว ทำงานพร้อมกันได้ 3 ช่อง |
| judge | AI ที่ให้คะแนนโค้ดก่อนเปิด PR ต้องใช้คีย์บทบาท judge |
| ด่านตรวจ 1–4 | ขั้นตรวจก่อนเปิด PR ดู [architecture.md](architecture.md#6-ด่านตรวจ) |
| key role | บทบาทของคีย์: `coder` (เขียนโค้ดหลัก), `judge` (ให้คะแนน), `scan` (สแกนหาปัญหา) |
| F6 failover | สลับไปผู้ให้บริการตัวถัดไปเมื่อโควตาหมด |
| ai-task | issue ที่เอเจนต์จะหยิบไปทำ |
| ai-plan | issue เสนอฟีเจอร์ที่รอการอนุมัติ |
| deep-scan | ให้ AI อ่านโค้ดแล้วรายงานปัญหา |

## 4. ข้อควรรู้เมื่อเปลี่ยนค่า

- **แก้ `config.yaml` ด้วยมือ หรือเปลี่ยนบทบาทคีย์:** ต้องรีสตาร์ทเอเจนต์ และรีโหลดหน้าก่อน เพราะรายการ engine ใน dropdown อ่านค่าตอนโหลดหน้า
- **ค่าใหม่ของ `merge_mode`:** มีผลกับการตัดสิน merge ครั้งถัดไป แต่ถ้าแก้ไฟล์เองให้รีสตาร์ทเพื่อความแน่นอน
- **เปลี่ยนเป็น `merge-all`:** GUI จะถามยืนยันก่อน

## 5. การทำงานร่วมกับ runner ที่รันนอก GUI

ถ้ารัน `python -m auto_dev_crew --loop` จากเทอร์มินัลเอง GUI จะเห็น runner นั้นและควบคุมการหยุดได้จากปุ่มหยุด

## 6. การทดสอบ GUI

- `python scripts/gui_smoke.py`: อ่านอย่างเดียว ตรวจว่าหน้าโหลดได้โดยไม่มี JS error (ต้องเปิด GUI อยู่และช่องว่าง)
- `python scripts/gui_e2e.py --repo OWNER/NAME`: กดปุ่มทำงานแบบ dry-run จริง ใช้ repo ทดสอบเท่านั้น และรันเมื่อช่องว่าง

รายละเอียดที่ [tools-and-scripts.md](tools-and-scripts.md)
